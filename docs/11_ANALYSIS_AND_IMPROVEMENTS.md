Версия 1.0 (2026-11-14). Статус: аналитический документ; код и данные не менялись.
Повод: запрос на новую версию приложения — ползунок количества вопросов и один большой набор-пример.
Источник принятых решений — `DECISIONS.md`. Спецификация изменений — `12_SPEC_V2.md`.

Обновление 2026-11-14: решения Q-01…Q-04 приняты и реализованы; итог — 106 тестов, JS 15.7 КБ,
пример `docs/templates/qa-core-239.json` в поставке. Разделы 2–3 фиксируют состояние до v2;
результат изменений отмечен по тексту.

## 1. Резюме

Приложение находится в рабочем состоянии MVP: 100 тестов зелёные, сборка проходит, JS занимает
15.7 КБ gzip из 120 КБ. Архитектура слоёв выдержана, запись состояния атомарна, контракты импорта
и backup версионированы.

Для версии 2 нужны две функции:

1. **Ползунок количества вопросов** вместо stepper. Это точечная замена одного экрана и его стилей;
   домен, хранилище и маршруты не меняются. Причина очевидна из данных: на наборе из 239 карточек
   stepper требует до 229 нажатий, чтобы дойти до максимума.
2. **Большой набор на 239 карточек.** По решению Q-01 он хранится в поставке как пример возможностей
   (`docs/templates/qa-core-239.json`), без автодобавления и без кнопки: файл импортируется вручную.
   Это +0 КБ к JS-бюджету и не меняет состояние пользователя само по себе.

**Блокирующая находка (исправлена):** приложенный JSON не проходил контракт импорта — 5 ответов
длиннее 200 символов, поэтому `parseDeckFile` отклонял файл целиком. По решению Q-02 ответы сокращены
(карточки 154, 209, 212, 215, 236); после правки — 0 нарушений, файл `docs/templates/qa-core-239.json`
импортируется.

Дополнительно найдены две мелкие несоответствия, заметные именно с большим набором: текст пустого
состояния содержит внутренний жаргон («на этапе 5»), а длинное название набора (71 символ) не
обрезается двумя строками, как требует `04_UX_SPEC.md`. Обе правки — по одной строке.

## 3. Текущее состояние

### 3.1 Продукт и границы

Персональное мобильное веб-приложение для обучения тестовыми карточками: iPhone, Safari 16.4+,
без сервера, аккаунтов и синхронизации; данные только в LocalStorage; офлайн после первого открытия;
язык интерфейса — русский. Ограничения MVP (четыре варианта ответа, один правильный, только текст,
без редактирования, без удаления, без графиков и геймификации) зафиксированы в `DECISIONS.md`
(D-010…D-019, D-130…D-132).

### 3.2 Архитектура

| Слой | Ключевые файлы | Ответственность | Меняется в v2 |
|---|---|---|---|
| `domain/` | `entities`, `state`, `import-deck`, `sessions`, `stats`, `validate`, `limits` | чистые правила, инварианты, лимиты | + правило дефолтного количества вопросов |
| `application/` | `store`, `test-session`, `ports` | сценарии, атомарная запись, тестовая сессия | без изменений |
| `infrastructure/` | `storage`, `network`, `sw-register`, `download` | адаптеры браузера | + загрузка JSON-ассета |
| `ui/` | `shell`, `navigation`, `screens/*`, `styles.css` | DOM и навигация, без бизнес-логики | замена stepper на ползунок |
| `shared/` | `config`, `strings`, `format`, `plural` | константы и все тексты | + версия и текст пустого состояния |
| `public/` | `manifest.webmanifest`, `icons/` | статические ассеты | + `decks/qa-core-239.json` |

Механизмы, на которые опирается v2:

- **Атомарная запись** (`Store.commit`): валидация состояния → один `setItem` → `revision++` → уведомление
  подписчиков. Импорт набора уже проходит этот путь целиком; отдельного кода сохранности не нужно.
- **Ограничение количества** дважды: `TestSession` зажимает `count` в `1…N`, экран настройки задаёт
  только значение по умолчанию. Поэтому слайдер не может «сломать» тестовый движок.
- **Маршрут теста** уже принимает `count` (`{ name: 'test'; deckId; count }`) — менять навигацию не нужно.
- **Service Worker** кеширует все файлы сборки рекурсивно (`build/sw.ts`), поэтому JSON в `public/`
  попадёт в precache автоматически, без правок SW.
- **Импорт и backup** не знают о происхождении набора: пример — обычный `personal-quiz-deck`
  v1, после импорта он неотличим от любого другого набора.

Вывод: обе функции ложатся в существующие слои без изменения схемы состояния, форматов JSON,
маршрутов и тестового движка.

### 3.3 Реализованные сценарии

Наборы (создание, архив, восстановление), карточки (создание, read-only просмотр, архив, история),

### 3.6 Сильные стороны

- **Слои не протекают:** домен не знает про DOM и LocalStorage, UI не содержит бизнес-логики.
- **Сохранность данных:** валидация до записи, один `setItem`, `revision`, защита квоты, экран
  повреждённого состояния без перезаписи.
- **Контракты строгие и версионированные:** импорт и backup отклоняют всё, что не проходит проверку,
  и не оставляют частичных изменений.
- **Малый вес и отсутствие зависимостей:** 15.7 КБ JS gzip, ноль runtime-зависимостей.
- **Тесты быстрые и детерминированные:** 100 тестов за ~4 с, без DOM и сети.

## 4. Варианты улучшений

### 4.1 Обязательные по запросу

**U-01. Ползунок количества вопросов.**
Что: заменить stepper на нативный `input[type=range]` (1…N) с крупным значением над шкалой.
Зачем: на 239 карточках выбор одним движением вместо 229 нажатий; значение по умолчанию `min(10, N)`
сохраняется (D-060). Цена: один экран + CSS + 12 строк правила в домене. Риск: низкий — `TestSession`
и так зажимает количество. Вердикт: в v2.

**U-02. Большой набор-пример.**
Что: поставлять набор `qa-core-239` (239 карточек) как пример возможностей в `docs/templates/`;
в состояние он не добавляется автоматически, кнопки нет — только ручной импорт через «Настройки».
Зачем: данные пользователя не меняются без его действия, а большой набор остаётся доступным примером.
Цена: 1 файл данных + тест шаблонов, ноль изменений кода. Риск: низкий — файл проходит тот же парсер,
что и импорт. Вердикт: в v2 (решение Q-01).

**U-03. Правка данных набора.**
Что: сократить 5 ответов до лимита 200 символов (конкретные замены — в `12_SPEC_V2.md`).
Зачем: без этого файл отклоняется целиком и функция U-02 не работает. Цена: 5 правок текста,
ноль изменений кода; альтернатива — поднять лимит ответа до 250 (контракт, UI, тесты, документы),
что противоречит принципу «не менять контракт ради одного файла». Вердикт: в v2 (сокращение).

### 4.2 Рекомендуемые попутные правки

**U-04. Текст пустого состояния.** Заменить «…импортируйте его из JSON на этапе 5» на нейтральное
«…или импортируйте его из JSON в настройках». Одна строка, убирает внутренний жаргон.
Вердикт: в v2 (P2).

**U-05. Обрезка названия набора двумя строками.** Добавить `-webkit-line-clamp: 2` к

Вердикт: в v2 (P2).

## 5. Как доставить набор: сравнение вариантов

| Вариант | JS-бюджет | Сложность | Офлайн | Ручной импорт того же файла | Итог |
|---|---|---|---|---|---|
| V-1. JSON в `public/decks/` + `fetch` при запуске | +0 КБ JS; +33 КБ gzip ассета однократно | низкая | да, SW precache | да, файл доступен по URL | не выбран (Q-01) |
| V-2. Динамический `import()` JSON-чанка | +0 КБ в основном чанке; чанк 33 КБ грузится только при первом запуске | средняя (Vite-чанк, `?raw`) | да | нет отдельного файла | не выбран |
| V-3. Статический импорт в основной бандл | +33 КБ gzip (итого ≈49 КБ) и разбор ~202 КБ строки при **каждом** запуске | низкая | да | нет | не выбран |
| V-4. Набор в поставке, импорт вручную | 0 | нулевая | не требуется | да | **принято**: пример в `docs/templates/` |

Отчёт `check-budget` суммирует все JS-чанки: V-1 даёт ≈16.5 КБ, V-2 и V-3 — ≈49 КБ; все варианты
укладываются в лимит 120 КБ, разница — в том, что V-1 не грузит данные при обычном запуске.

Решение пользователя (Q-01): V-1 не выбран — набор хранится в коде как пример (V-4), без
автодобавления и без кнопки. Сравнение сохранено как история вариантов.

Почему V-1 был рекомендован: файл остаётся обычным `personal-quiz-deck` v1 (его можно скачать
и импортировать вручную), SW кеширует его автоматически, JS-бюджет не растёт, а первый запуск и так
требует сети (D-103). Но по решению Q-01 приложение не меняет данные само: пример лежит в поставке
и импортируется вручную, поэтому V-1 не реализуется.

| Правка данных исказила смысл ответа | контент | 5 замен вычитаны, тест валидации файла |
| Слайдер на 1000 карточек неточен | выбор количества | шаг 1, значение видно числом; при необходимости — U-06 |
