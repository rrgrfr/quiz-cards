# Реестр решений — единственный источник принятых решений

Проект: персональное приложение для обучения тестовыми карточками («Карточки», internal id `personal-quiz`).
Версия файла: 1.0 · 2026-11-13 · закрывает OQ-001…OQ-010 и открытые вопросы аудита.
Приоритет: этот файл выше `03_DECISION_REGISTER.md`, `02_PRD.md`, `05_TECHNICAL_SPEC.md`, `04_UX_SPEC.md` (см. R-5).

## R. Правила ведения файла

**R-1. Append-only.** Записи не удаляются. Текст принятого решения не переписывается и не сокращается задним числом: история решений — часть спецификации.

**R-2. Изменение — только новой записью.** Новое решение получает следующий свободный `D-NNN` и статус «Заменяет D-MMM»; старая запись остаётся на месте, у неё дописывается только пометка «Заменено D-NNN». Удалять и «чистить» старые записи нельзя.

**R-3. Кратчайшая выжимка.** Каждая запись содержит: решение, причину и границы, только если без них решение нельзя применить. Никаких длинных обоснований и пересказов обсуждений.

**R-4. Нумерация.** ID выдаются по возрастанию, не переиспользуются; пропуски допустимы для группировки по темам.

**R-5. Приоритет документов.** `DECISIONS.md` → `03_DECISION_REGISTER.md` → `02_PRD.md` → `05_TECHNICAL_SPEC.md` → `04_UX_SPEC.md`.

**R-6. Закрытие вопроса.** Вопрос считается закрытым только после записи здесь. Обсуждение без записи решением не является.

**R-7. Правила неизменяемы.** R-1…R-7 не меняются; новое правило добавляется как R-8 и далее, в конец раздела.

**R-8. Статусы.** Только «Принято» и «Заменено D-NNN». Других статусов нет.

**R-9. Порядок добавления.** Новые разделы и записи добавляются в конец файла; сортировка и перенумерация запрещены.

## 1. Процесс и документы

- **D-001. Источник решений.** Этот файл — единственный реестр принятых решений; 03, 06 и 09 хранятся как история требований. *Причина:* три реестра открытых вопросов расходились между собой.
- **D-002. Обязательность правил R.** Правила R-1…R-9 действуют для всех участников, включая агента и будущие сессии. *Причина:* причины решений не должны теряться при смене курса.
- **D-003. VCS.** Git-репозиторий, ветка `main`, conventional commits, тег `v1.0.0` на приёмке MVP. *Причина:* истории изменений сейчас нет, тег фиксирует приёмку.
- **D-004. Обновление документов.** Документы правятся в конце каждого этапа; изменение поведения/схемы требует новой записи D. *Причина:* спека не расходится с кодом.
- **D-005. Definition of Done этапа.** Код + тесты + ручная проверка на iPhone + обновлённые документы + запись решения. *Причина:* единый критерий завершения.
- **D-006. Момент закрытия.** С версии 1.0 этого файла OQ-001…OQ-010 и вопросы аудита считаются закрытыми. *Причина:* фиксация точки, после которой решения обязательны.
- **D-007. JSON-контракт утверждён здесь.** Форматы `personal-quiz-deck` и `personal-quiz-backup` v1 (D-040…D-057) считаются утверждёнными на этапе 0; этап 5 их только реализует. *Причина:* устранено противоречие «схема на этапе 0 и на этапе 5» (C-02).

## 2. Платформа, стек, инфраструктура

- **D-010. Стек.** TypeScript (strict) + Vite + нативный DOM, без UI-фреймворка. *Причина:* минимальный вес и минимум зависимостей; домен отделён от UI, поэтому слой представления можно заменить позже. Решение закрывает OQ-001 и может быть заменено новой записью.
- **D-011. Пакетный менеджер.** npm; dev-зависимости: vite, typescript, vitest, eslint, prettier. В рантайме зависимостей нет. *Причина:* предсказуемые обновления, ничего лишнего в бандле.
- **D-012. Тесты.** Vitest: unit + integration на фейковом адаптере хранения. E2E Playwright отложен, вместо него ручной чек-лист iPhone. *Причина:* E2E тяжёл для MVP без сервера, ручная проверка Safari обязательна.
- **D-013. Минимальная версия.** iOS/Safari 16.4+. iPhone — целевое устройство; iPad работает best-effort без отдельного тестирования. *Причина:* покрывает большинство актуальных устройств и нужные API (SW, download, crypto.randomUUID).
- **D-014. Хостинг.** Статический HTTPS-хостинг, GitHub Pages + GitHub Actions; собственный домен не обязателен. *Причина:* HTTPS обязателен для Service Worker, деплой из репозитория бесплатен.
- **D-015. Сборка.** Только статические файлы, без SSR; все ассеты свои, CDN в рантайме запрещён. *Причина:* офлайн и независимость от сети.
- **D-016. Название.** Рабочее «Карточки», internal id `personal-quiz`; название задаётся в одном конфиге. *Причина:* нужно для manifest и заголовка, меняется дёшево.
- **D-017. Язык интерфейса.** Русский; все строки в одном модуле. *Причина:* локализация позже без переписывания экранов.
- **D-018. PWA.** Manifest, `apple-touch-icon`, собственный SW; установка не обязательна, но рекомендуется в UI. *Причина:* PD-002 и снижение риска очистки данных iOS.
- **D-019. Ориентация и safe-area.** Портрет основной, ландшафт рабочий; учитываются safe-area и «челка». *Причина:* управление одной рукой на iPhone.

## 3. Хранение и модель данных

- **D-020. Хранилище.** LocalStorage, один ключ `pq.state.v1`, единый JSON состояния. *Причина:* простая атомарная запись; PD-037.
- **D-021. UI-флаги.** Отдельный ключ `pq.ui.v1` (подсказки, «показан онбординг»), в backup не входит. *Причина:* потеря настроек интерфейса безвредна.
- **D-022. Адаптер хранения.** Интерфейс load/save, домен не знает про LocalStorage. *Причина:* замена на IndexedDB без правок логики.
- **D-023. ID.** UUID v4 (`crypto.randomUUID()`), глобально уникальны. *Причина:* генерация без сервера и устойчивость к слиянию данных.
- **D-024. Время.** ISO 8601 UTC; при импорте `createdAt`/`updatedAt` = момент импорта. *Причина:* однозначный формат и сортировка.
- **D-025. Поля времени.** У Card нет `updatedAt` (карточка не редактируется); `Deck.updatedAt` обновляется, но в UI v1 не используется. *Причина:* не плодить неиспользуемые поля.
- **D-026. Settings.** Зарезервированный пустой объект, в UI v1 не показывается. *Причина:* формат backup стабилен, настройки появятся позже.
- **D-027. Сортировка.** Наборы — по `createdAt` desc; карточки — по `createdAt` asc; архив отдельно в конце списка. *Причина:* новые сверху, внутри набора — порядок добавления. Закрывает OQ-009.
- **D-028. Попытки в процессе.** Во время теста попытки хранятся в памяти; в хранилище попадают только с завершённой сессией. *Причина:* не остаётся осиротевших попыток, прерывание ничего не портит.
- **D-029. Инварианты сессии.** При загрузке и restore проверяется: `questionCount` = число попыток, `correctCount` = число верных, `completedAt` ≥ `startedAt`. *Причина:* статистика не ломается от повреждённого файла.
- **D-030. Версия состояния.** `schemaVersion` 1; при повреждении или неизвестной версии — экран ошибки с выгрузкой сырых данных и сбросом. *Причина:* данные не затираются молча.
- **D-031. Атомарность записи.** Один `setItem`; ошибка записи = сохранение не выполнено, показывается сообщение. *Причина:* НФТ «не сообщать об успехе, если запись не удалась».
- **D-032. Защита квоты.** Перед записью оценка объёма; при >4.5 МБ или ошибке `setItem` — отказ с советом экспортировать/сбросить статистику. *Причина:* квота Safari ~5 МБ, явная ошибка лучше потери.
- **D-033. История без авто-обрезки.** Автоматической обрезки сессий нет; лимиты импорта держат базу компактной. *Причина:* завершённые результаты не удаляются без ведома пользователя.
- **D-034. Мультивкладка.** Last-write-wins; при возврате фокуса сверяется `revision`, при расхождении — перезагрузка данных с уведомлением. *Причина:* дешёвая защита от рассинхрона.
- **D-035. Revision.** Состояние содержит целое `revision`, увеличивается при каждой записи. *Причина:* сверка версий между вкладками.

## 4. Импорт JSON

- **D-040. Формат импорта.** `personal-quiz-deck`, `schemaVersion` 1, один набор на файл. *Причина:* проще валидация и UI; несколько наборов — будущая версия. Закрывает OQ-003.
- **D-041. Структура.** `deck{title, description?, cards[]}`; `card{question, answers[4], correctAnswerIndex 0…3, explanation?}`. *Причина:* соответствует PRD и не требует ID в файле.
- **D-042. Семантика импорта.** Импорт добавляет новый набор; существующие данные не меняются. *Причина:* отличается от восстановления и предсказуем.
- **D-043. Дубликат названия.** Предупреждение и подтверждение; создаётся отдельный набор, слияния нет. *Причина:* без конфликтов ID и сложного merge. Закрывает OQ-004.
- **D-044. Строгость.** Типы проверяются строго, неизвестные поля игнорируются. *Причина:* расширение схемы без поломки старых файлов.
- **D-045. Текст и варианты.** Все тексты trim; пустые после trim — ошибка; ровно 4 непустых варианта; дубли вариантов без учёта регистра — ошибка. *Причина:* устраняет неоднозначность правильного ответа.
- **D-046. Лимиты.** Файл 2 МБ; карточек 1…1000; title 120, description 200, question 500, answer 200, explanation 1000 символов. *Причина:* квота LocalStorage и читаемость на iPhone.
- **D-047. Минимум карточек.** Набор без карточек отклоняется. *Причина:* пустой набор бесполезен и даёт пустой пул теста.
- **D-048. Ошибки импорта.** Собираются все (до 20) с номером карточки и полем; при любой ошибке не пишется ничего. *Причина:* атомарность и понятная диагностика.
- **D-049. Результат импорта.** Набор и карточки активны; ID генерируются, `correctAnswerIndex` превращается в `correctAnswerId`. *Причина:* соответствие внутренней модели со стабильными ID (C-03).

## 5. Backup и восстановление

- **D-050. Формат backup.** `personal-quiz-backup` v1: `appVersion`, `exportedAt`, `data{decks, cards, sessions, settings}`. *Причина:* полный слепок и место для будущих полей.
- **D-051. Попытки.** Хранятся внутри сессии (`attempts[]`); незавершённые сессии не экспортируются. *Причина:* целостность истории (A-16).
- **D-052. Валидация restore.** Формат, версия, уникальность ID, ссылочная целостность, инварианты D-029; любая ошибка — отказ без изменений. *Причина:* повреждённый файл не должен уничтожать базу.
- **D-053. Замена.** Подтверждение с количеством наборов/карточек/сессий, затем замена всего состояния одним ключом. *Причина:* атомарная замена и информированное согласие.
- **D-054. Версии.** Поддерживается только `schemaVersion` 1; старые и новые отклоняются; миграции — будущая версия. *Причина:* MVP без legacy-кода.
- **D-055. Экспорт.** Blob + `a[download]`, имя `quiz-backup-ГГГГ-ММ-ДД-ЧЧмм.json`; fallback `navigator.share`; проверка на iPhone на этапе 1. *Причина:* системный механизм iOS без библиотек. Закрывает OQ-010.
- **D-056. Офлайн.** Импорт, экспорт и восстановление работают без сети. *Причина:* FR-032.
- **D-057. Предупреждение об экспорте.** Файл — открытый текст; перед экспортом показывается предупреждение. *Причина:* пользователь должен знать о риске при передаче файла.

## 6. Тестовый режим

- **D-060. Количество вопросов.** Stepper 1…N, значение по умолчанию `min(10, N)`; при N = 0 запуск заблокирован с подсказкой. *Причина:* минимум решений и понятный дефолт. Закрывает X-12, X-13, A-11. *Заменено D-135 в части элемента управления.*
- **D-061. Пул.** Активные карточки активного набора; архивные исключены. *Причина:* FR-037.
- **D-062. Выбор и перемешивание.** N уникальных случайных карточек; варианты перемешиваются Фишером–Йетсом, `crypto.getRandomValues` при наличии. *Причина:* равномерность без зависимостей; FR-023 выполняется самим отсутствием повторов.
- **D-063. Фиксация ответа.** Первое нажатие фиксирует ответ; кнопки блокируются сразу плюс guard 300 мс. *Причина:* исключить двойную попытку.
- **D-064. Переход дальше.** После ответа — подсветка верного/неверного и объяснение; переход кнопкой «Далее», на последнем вопросе — «Итог». *Причина:* контроль темпа без случайных пропусков. Закрывает OQ-008.
- **D-065. Выход из теста.** Назад или таб во время теста — подтверждение; после подтверждения сессия не сохраняется. *Причина:* PD-018.
- **D-066. Прогресс.** «Отвечено/запланировано» и число верных в текущей сессии. *Причина:* FR-035.
- **D-067. Итог.** Верные, неверные, процент; кнопки «К набору» и «Ещё раз». *Причина:* закрывает сценарий без лишних экранов.
- **D-068. Сохранение сессии.** Ровно один раз при завершении; повторное сохранение исключено флагом. *Причина:* без дублей в статистике.
- **D-069. Агрегаты.** Отдельно не хранятся, считаются из сессий. *Причина:* нет расхождений между счётчиками и историей.

## 7. Статистика

- **D-070. Процент.** `round(верные / ответы × 100)`; при нуле ответов — «—». *Причина:* одна формула на все экраны.
- **D-071. По наборам.** Только активные; архивные скрыты и возвращаются с восстановлением набора. *Причина:* меньше шума, история не теряется.
- **D-072. По карточке.** Экран карточки read-only: последние 20 попыток и итоги. *Причина:* FR-028 без отдельной аналитики.
- **D-073. Сброс статистики.** Удаляет все сессии и попытки, контент не трогает; подтверждение с предупреждением о необратимости. *Причина:* PD-025/PD-039.
- **D-074. Охват сброса.** `settings` и архив не затрагиваются. *Причина:* сброс относится только к истории.

## 8. UX, навигация, архив

- **D-080. Табы.** «Наборы», «Статистика», «Настройки»; иконки — собственные SVG. *Причина:* PD-027 без иконочных библиотек.
- **D-081. Пустые состояния.** Наборы, архив, статистика; с явным CTA. *Причина:* понятный первый шаг.
- **D-082. Экран набора.** Описание (необязательное, до 200), счётчик активных, список карточек, запуск теста, добавить карточку, архивировать, архив карточек. *Причина:* одна точка управления набором; закрывает A-06.
- **D-083. Экран карточки.** Read-only: вопрос, 4 варианта, отметка верного, объяснение, история, архивировать. *Причина:* PD-021, но нужен доступ к истории (C-06).
- **D-084. Редактирование набора.** В v1 нет; исправление — архив и создание нового. *Причина:* единое правило «не редактируем», меньше экранов (A-07).
- **D-085. Архивирование набора.** Не каскадирует: карточки хранят свои флаги; тест доступен только у активного набора. *Причина:* простые независимые флаги (A-09).
- **D-086. Архив.** Отдельный экран, восстановление по одной сущности. *Причина:* без массовых операций (A-08).
- **D-087. Формы.** Safe-area, клавиатура не перекрывает поля, у полей ответов отключены autocorrect/autocapitalize. *Причина:* реальные проблемы ввода на iOS.
- **D-088. Базовые требования.** Кнопки ≥44 pt, контраст ≥4.5, Dynamic Type, подписи для VoiceOver. *Причина:* доступность без отдельного этапа (G-05).
- **D-089. Маршрутизация.** URL-роутера в v1 нет: экраны в памяти, системная «назад» выходит из приложения. *Причина:* не нужен сервер, меньше кода; ограничение зафиксировано.
- **D-090. Тема.** Только тёмная, через CSS-переменные, без переключателя. *Причина:* PD-030.
- **D-091. Подтверждения.** Restore, сброс статистики, выход из теста, импорт с совпадающим названием. *Причина:* только необратимые и рискованные действия.
- **D-092. Предупреждение о backup.** Отдельное сообщение о том, что файл не шифруется. *Причина:* приватность.
- **D-093. Онбординг-подсказка.** Одноразовая «Добавить на экран Домой» и про регулярный экспорт; флаг в `pq.ui.v1`. *Причина:* снижает риск очистки данных iOS (G-03).
- **D-094. Тексты ошибок.** Единый каталог сообщений по кодам. *Причина:* проверяемость обратной связи и единый тон (G-07).
- **D-095. Критерии стиля.** Системный шрифт, отступы 16, радиус 12, без градиентов и декора; эталон — согласованные скриншоты этапа 1. *Причина:* «эстетика Apple» становится проверяемой (T-01).

## 9. Офлайн и Service Worker

- **D-100. SW.** Собственный service worker без библиотек; precache оболочки, версия из сборки. *Причина:* контроль и отсутствие зависимостей.
- **D-101. Стратегии кеша.** Навигация `network-first` с fallback из кеша; хешированные ассеты `cache-first`. *Причина:* свежая версия при сети, работа без сети.
- **D-102. Обновление.** Новый SW — плашка «Обновить», затем `skipWaiting` и перезагрузка. *Причина:* не смешивать версии ресурсов (G-09).
- **D-103. Первый запуск.** Требует сети; до активации SW показывается загрузка; без SW — предупреждение. *Причина:* PD-044.
- **D-104. Индикатор офлайн.** Показывается при `navigator.onLine === false`. *Причина:* понятность состояния.
- **D-105. Очистка данных iOS.** Риск признан: приложение рекомендует установку и экспорт, но не обещает сохранность. *Причина:* честное ограничение платформы (C-08, G-03).

## 10. Безопасность

- **D-110. Вывод текста.** Только через `textContent`; `innerHTML` с пользовательскими данными запрещён. *Причина:* XSS через импортированный текст.
- **D-111. CSP.** `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'`. *Причина:* запрет сторонних загрузок.
- **D-112. Отсутствие сетевых функций.** Нет телеметрии, аналитики, внешних запросов и шифрования. *Причина:* PD-017/PD-038 и вне MVP.
- **D-113. Недоверенный импорт.** Лимиты, `try/catch`, отказ при аномалиях. *Причина:* устойчивость к вредным файлам.

## 11. Качество, тестирование, приёмка

- **D-120. Покрытие.** Unit: валидация, перемешивание, подсчёт, сериализация; integration: адаптер, импорт/экспорт, restore. *Причина:* критичные инварианты.
- **D-121. Ручной чек-лист iPhone.** Офлайн, экспорт, импорт, выбор файла, обновление SW, очистка данных. *Причина:* то, что не проверяется в jsdom.
- **D-122. Цели производительности.** JS ≤120 КБ gzip, TTI ≤2 с на iPhone 12/4G, отклик ≤50 мс, импорт 1000 карточек ≤500 мс. *Причина:* измеримость НФТ (N-01).
- **D-123. Критерий приёмки MVP.** Все Must-FR выполнены, блокирующие дефекты из 07 отсутствуют, ручной чек-лист пройден. *Причина:* единая приёмка.
- **D-124. Ёмкость.** 100 наборов, 5000 карточек, файл 2 МБ, сессии до квоты. *Причина:* совместимо с 5 МБ Safari (N-02).
- **D-125. Трассировка.** Матрица FR → сценарий → тест ведётся в 07; каждый Must-FR имеет хотя бы один сценарий. *Причина:* устранение T-04.
- **D-126. Фикстуры.** Валидные и невалидные JSON-файлы в `tests/fixtures`, список в 07. *Причина:* тесты импорта и restore воспроизводимы (T-05).

## 12. Границы v1 и пути апгрейда

- **D-130. Удаление.** Hard delete в v1 нет; только архив. *Причина:* PD-016/PD-041; закрывает OQ-005.
- **D-131. Полное удаление данных.** В v1 нет, кроме сброса при повреждённом состоянии. *Причина:* не добавлять функцию вне MVP (G-08).
- **D-132. Направления роста.** IndexedDB через адаптер, UI-фреймворк поверх домена, i18n, несколько наборов в импорте, миграции версий, синхронизация — отдельными решениями. *Причина:* лёгкий v1 без потери направлений развития.

## 16. Дополнения этапа 1

- **D-133. Пакетный менеджер — pnpm.** Заменяет часть D-011 (npm): npm отсутствует в среде разработки, доступен pnpm 11. Остальной состав dev-зависимостей D-011 не меняется. *Причина:* среда не содержит npm, pnpm даёт тот же результат и lock-файл; решение обратимо новой записью.
- **D-134. Инициализация Git отложена.** Заменяет часть D-003: git в среде отсутствует, поэтому репозиторий и первый коммит создаются, когда git станет доступен; workflow публикации на GitHub Pages добавлен заранее. *Причина:* нельзя выполнить git-операции без установленного git; это не меняет решение о VCS.

## 17. Дополнения v2

- **D-135. Количество вопросов — ползунок.** Заменяет D-060 в части элемента управления: нативный `range` 1…N, значение по умолчанию `min(10, N)` сохраняется, выбранное число видно над шкалой; при N = 1 ползунок заблокирован, при N = 0 запуск заблокирован. *Причина:* на наборе из 239 карточек stepper требует до 229 нажатий; ползунок даёт выбор одним движением.
- **D-136. Большой набор-пример.** Набор `qa-core-239` (239 карточек) хранится в поставке как пример возможностей (`docs/templates/qa-core-239.json`) и импортируется вручную; автоматически в состояние не добавляется, кнопки и отдельного экрана нет. *Причина:* данные пользователя не меняются без его действия, а большой набор остаётся доступным примером (Q-01).
- **D-137. Лимиты не меняются под пример.** Файл — обычный `personal-quiz-deck` v1; лимит ответа остаётся 200, 5 ответов сокращены до лимита. *Причина:* не менять утверждённый контракт ради одного файла (D-046).
