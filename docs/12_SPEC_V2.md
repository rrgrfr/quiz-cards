# Спецификация v2.1: ползунок количества вопросов и готовые наборы

Версия 1.2 (2026-11-15). Статус: реализовано; решения Q-01…Q-04 и уточнение по готовым наборам
подтверждены пользователем. Основание: `11_ANALYSIS_AND_IMPROVEMENTS.md`.
Источник решений — `DECISIONS.md` (D-135…D-138).

Спецификация описывает две функции:

1. ползунок выбора количества карточек перед началом теста;
2. готовые наборы: кнопка «Выбрать готовый» на экране «Наборы» и экран выбора.

Ключевое решение по набору (Q-01, уточнение 2026-11-15): набор хранится в поставке (`public/decks/`),
но **не добавляется автоматически**; он предлагается на экране «Наборы» и добавляется только
по явному действию пользователя (D-138).

## 2. Функция V2-F-01 — ползунок количества вопросов

### 2.1 Требования

| ID | Требование |
|---|---|
| V2-FR-01 | На экране «Настройка теста» вместо stepper — нативный `input[type="range"]` с `min=1`, `max=N`, `step=1`, где `N` — число активных карточек набора |
| V2-FR-02 | Значение по умолчанию — `min(10, N)` (сохраняется правило D-060) |
| V2-FR-03 | Выбранное число видно над ползунком и обновляется при каждом движении |
| V2-FR-04 | «Начать тест» передаёт выбранное число в существующий маршрут `{ name: 'test', deckId, count }` |
| V2-FR-05 | При `N = 1` ползунок заблокирован, значение `1`, тест запускается |
| V2-FR-06 | При `N = 0` показывается существующий экран-заглушка «Нет активных карточек»; поведение не меняется |
| V2-FR-07 | Доступность: у ползунка есть доступное имя, значение читается VoiceOver, зона касания ≥44 pt (D-088) |
| V2-FR-08 | Значение не запоминается между сессиями: при каждом входе — `min(10, N)` (запоминание — задача U-09) |

### 2.2 UX и поведение

```
Настройка теста
Доступно 239 карточек

Сколько вопросов?
        10
[—————————o———————————————————————]
[          Начать тест            ]
```

| Ситуация | Ползунок | Значение | «Начать тест» |
|---|---|---|---|
| `N = 0` | экран-заглушка, контролов нет | — | — |
| `N = 1` | `disabled`, `min = max = 1` | 1 | активна, тест из 1 вопроса |
| `1 < N < 10` | `max = N`, стоит в конце | `N` | активна |
| `N ≥ 10` | `max = N`, стоит на 10 | 10 | активна |
| Перетаскивание | значение меняется | обновляется `input`-событием | активна |
| Стрелки клавиатуры | ±1 | обновляется | активна |

Почему значение над шкалой, а не сбоку: на ширине iPhone (~343 px) шкала получает полную ширину,
это важно при 239 и более значениях; крупное число читается как основной результат выбора.
Почему без `aria-live`: нативный `range` сам объявляет значение VoiceOver, живой регион дал бы
двойное озвучивание.

### 2.6 Критерии приёмки

1. На экране настройки теста нет кнопок `−`/`+`; есть ползунок и крупное число.
2. Дефолт для набора из 239 карточек — 10; для набора из 3 — 3; для 1 — 1 и `disabled`.
3. Перетаскивание до конца запускает тест на 239 вопросов; итог показывает 239.
4. VO: «Сколько вопросов?, 10, Доступно 239 карточек»; изменение значения озвучивается.
5. Возврат из результата «К набору» → «Начать тест» снова показывает 10.
6. Набор без активных карточек по-прежнему показывает заглушку.

### 3.3 Поток добавления

1. Пользователь открывает «Наборы» → «Выбрать готовый».
2. Экран рендерит каталог; для каждого набора ищется существующий по названию (активный или архивный).
3. «Добавить»: кнопка блокируется, файл загружается `fetch` с `document.baseURI` (same-origin),
   разбирается `parseDeckFile` и добавляется `store.importDeck`.
4. Успех: тост и переход к набору. Ошибка: тост, состояние не меняется, кнопка разблокируется.
5. Повторное добавление отклоняется по названию — до загрузки файла; кнопка показывает «Уже добавлен».
6. Офлайн: файл в precache SW, импорт работает после первого открытия (D-103, D-056).
7. Обновление содержимого готового набора в v2.1 не поддерживается: у пользователя остаётся
   уже добавленная копия; изменение — новой записью решения.

### 3.4 Модули

**`src/infrastructure/ready-decks.ts`** — загрузка ассета:

```ts
/** Fetch a ready-made deck asset from the app origin (precached by the SW). */
export async function loadReadyDeck(file: string): Promise<string> {
  const url = new URL(`./${file}`, document.baseURI);
  const response = await fetch(url);
  if (!response.ok) throw new Error(`Ready deck: HTTP ${response.status}`);
  return response.text();
}
```

**`src/application/ready-decks.ts`** — сценарий с защитой от дубля и ошибками:

```ts
export type ReadyDeckError = 'already-added' | 'load-failed' | 'invalid-deck';

export type AddReadyDeckResult =
  | { ok: true; value: Deck }
  | { ok: false; error: ReadyDeckError | StoreError };

export async function addReadyDeck(
  store: Store,
  deck: ReadyDeck,
  load: (file: string) => Promise<string>,
): Promise<AddReadyDeckResult> {
  if (store.get().decks.some((item) => item.title === deck.title)) {
    return { ok: false, error: 'already-added' };
  }

  let raw: string;
  try {
    raw = await load(deck.file);
  } catch {
    return { ok: false, error: 'load-failed' };
  }

  const parsed = parseDeckFile(raw);
  if (!parsed.ok) return { ok: false, error: 'invalid-deck' };

  return store.importDeck(parsed.value);
}
```

### 3.5 Крайние случаи

| Случай | Поведение |
|---|---|
| Набор уже есть в списке | «Уже добавлен», «К набору», файл не загружается |
| Набор в архиве | «В архиве», «Открыть архив», повторно не добавляется |
| `fetch` вернул 404/500, сеть недоступна | тост, состояние не меняется, кнопка активна |
| Файл повреждён/нарушает контракт | тост, ничего не добавлено; тест каталога не даст выпустить такой файл |
| Квота LocalStorage | `importDeck` → `save-quota`, состояние не меняется |
| Лимит наборов/карточек | `importDeck` → `limit-exceeded`, состояние не меняется |
| Двойное нажатие | кнопка блокируется до завершения операции |
| Офлайн после первого запуска | файл в precache, добавление работает |
| Пустой каталог | экран показывает заголовок и лид; список пуст |

### 3.6 Критерии приёмки

1. На экране «Наборы» под «Создать набор» есть «Выбрать готовый» и пояснение.
2. Кнопка открывает «Готовые наборы» с карточкой набора: название, описание, «239 карточек», «Добавить».
3. «Добавить» добавляет набор ровно один раз, открывает его; в списке 239 карточек.
4. Повторный вход: «Уже добавлен» и «К набору»; дубля нет.
5. Архивированный набор: «В архиве» и «Открыть архив».
6. Ошибка загрузки/квоты: сообщение, состояние не меняется.
7. Автодобавления нет: без действия пользователя набор в состоянии не появляется.
