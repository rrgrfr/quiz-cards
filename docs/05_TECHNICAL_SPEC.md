# Техническая спецификация

Версия 1.2 (2026-11-13). Источник принятых решений — `DECISIONS.md` (D-010…D-035, D-100…D-113).

## Ограничения
Клиентское статическое приложение для Safari на iPhone (iOS 16.4+), без сервера, аккаунтов и синхронизации. Данные — только в LocalStorage. Офлайн после первого успешного открытия. Хостинг статический с HTTPS (обязателен для Service Worker). Язык интерфейса — русский.

## Стек
- TypeScript (strict) + Vite; нативный DOM, без UI-фреймворка (D-010).
- npm; dev-зависимости: `vite`, `typescript`, `vitest`, `eslint`, `prettier`; в рантайме зависимостей нет (D-011).
- Тесты: Vitest, unit и integration на фейковом адаптере хранения; E2E отложен, вместо него ручной чек-лист iPhone (D-012).
- Стили: обычный CSS с переменными, системный шрифт; без CSS-фреймворков.

## Структура проекта (план)
```
src/
  domain/            модель и чистые правила: card, deck, session, stats, shuffle
  application/       сценарии: createDeck, createCard, archive, runTest, importDeck, restoreBackup, resetStats
  infrastructure/    storage-adapter (localStorage), json-parse, file-download, service-worker-registration
  ui/                экраны и компоненты, без бизнес-логики
  shared/            строки, коды ошибок, конфиг (название, лимиты, версии схем)
public/
  manifest.webmanifest, sw.js, icons/
tests/
  unit/, integration/, fixtures/
```
Домен и сценарии не импортируют UI и браузерные API напрямую — только через адаптеры (D-022).

## Логическая архитектура
1. **Presentation/UI** — экраны, компоненты, ввод.
2. **Application logic** — сценарии, оркестрация, проверки.
3. **Domain model** — Deck, Card, StudySession, Attempt, Settings, правила статистики.
4. **Persistence adapter** — `load()`/`save(state)`; единственная точка работы с LocalStorage.
5. **Import/export service** — разбор, валидация, сериализация JSON.
6. **Offline shell** — Service Worker и кеш статических ресурсов.

Зависимости направлены внутрь: UI → application → domain; infrastructure реализует интерфейсы, объявленные внутри.

## Состояние и хранилище
- Ключ `pq.state.v1`; единый JSON: `{ schemaVersion: 1, revision, decks, cards, sessions, settings }` (D-020, D-035).
- UI-флаги — `pq.ui.v1`, не входят в backup (D-021).
- Чтение: parse → проверка структуры и инвариантов → при ошибке экран ошибки без перезаписи (D-030).
- Запись: изменение → валидация состояния → сериализация → проверка объёма (>4.5 МБ — отказ) → один `setItem` → `revision++` (D-031, D-032, D-035).
- Ошибка `setItem`: состояние не считается сохранённым, показывается сообщение; успех не сообщается (NFR-006).
- Мультивкладка: last-write-wins; при возврате фокуса сравнивается `revision`, при расхождении данные перезагружаются с уведомлением (D-034).
- LocalStorage синхронный и ограничен квотой Safari (~5 МБ); при росте данных адаптер заменяется на IndexedDB без изменения домена (D-022, D-132).

## Модель данных (кратко)
Подробные правила — в `06_DATA_AND_JSON_FORMAT.md`. Сущности: `Deck`, `Card`, `AnswerOption`, `StudySession`, `Attempt`; ID — UUID v4; время — ISO 8601 UTC (D-023, D-024).

## Импорт и экспорт
- Импорт: `personal-quiz-deck` v1, один набор на файл; полная валидация до записи; при любой ошибке — ноль изменений; лимиты и коды ошибок — в 06 (D-040…D-049).
- Готовые наборы: каталог в `src/shared/ready-decks.ts`, файл `public/decks/qa-core-239.json` загружается по действию пользователя и добавляется через `importDeck` (D-138); автодобавления нет, дубликат по названию отклоняется.
- Экспорт: `personal-quiz-backup` v1; Blob + `a[download]`, fallback `navigator.share`; предупреждение об открытом тексте (D-050, D-055).
- Восстановление: валидация → подтверждение с количеством сущностей → замена одним `setItem` (D-052, D-053).

## Тестовая сессия (поток)
1. Взять активные карточки активного набора (D-061).
2. Ограничить количество доступным пулом (FR-036); количество задаётся ползунком 1…N (D-135).
3. Случайно выбрать N уникальных карточек; перемешать варианты Фишером–Йетсом (D-062).
4. Сохранить связь вариантов со стабильными ID; правильность проверять по `correctAnswerId` (D-049).
5. Первое нажатие фиксирует попытку, кнопки блокируются, guard 300 мс (D-063).
6. Показать обратную связь и объяснение; переход кнопкой «Далее»/«Итог» (D-064).
7. По завершении сохранить сессию один раз (D-068).
8. Незавершённую сессию не сохранять и не восстанавливать (D-028, D-065).

## Офлайн и Service Worker
- Собственный `sw.js` без библиотек; версия кеша берётся из сборки (D-100).
- `install`: precache оболочки (HTML, JS, CSS, иконки, manifest) и готовых наборов из `public/decks/`.
- Навигационные запросы: network-first с fallback из кеша; хешированные ассеты — cache-first (D-101).
- Новый SW: плашка «Обновить» → `skipWaiting` → перезагрузка (D-102).
- Первый запуск требует сети; до активации SW показывается загрузка; без поддержки SW — предупреждение (D-103).
- Индикатор офлайн при `navigator.onLine === false` (D-104).
- Данные и кеш могут быть очищены iOS/Safari; приложение рекомендует установку и экспорт (D-105).

## Безопасность
- Пользовательский текст выводится только через `textContent`; `innerHTML` с данными запрещён (D-110).
- CSP: `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'` (D-111).
- Нет телеметрии, аналитики, внешних запросов и шифрования (D-112).
- Импорт недоверенный: лимиты, `try/catch`, отказ при аномалиях (D-113).

## Производительность
- Бюджет JS ≤120 КБ gzip; TTI ≤2 с на iPhone 12/4G; отклик ≤50 мс; импорт 1000 карточек ≤500 мс (D-122).
- Длинные списки — постраничная отрисовка или виртуализация только при необходимости; измерять на реальном устройстве.
- Любая ошибка записи сообщается явно; успех не показывается, если запись не состоялась.

## Ограничения и известные компромиссы v1
- Нет URL-роутинга: экраны в памяти, системная «назад» выходит из приложения (D-089).
- Нет многопользовательской синхронизации и блокировок: last-write-wins между вкладками (D-034).
- Нет миграций схемы: поддерживается только версия 1 (D-054).
- Нет шифрования локальных данных и backup (D-112).
- Очистка данных браузером не предотвращается приложением (D-105).

## Сборка и публикация

- GitHub Actions: сборка, тесты, публикация на GitHub Pages; HTTPS обязателен (D-014).
- Ассеты только собственные; CDN в рантайме запрещён (D-015).

## Инструменты и проверки

- Ручной чек-лист iPhone: первый запуск, офлайн, установка на экран, экспорт, импорт файла, восстановление, обновление SW, очистка данных Safari (D-121).
