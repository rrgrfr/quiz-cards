# План реализации

Версия 1.8 (2026-11-13). Решения — в `DECISIONS.md`; план описывает порядок работ.

## Этап 0. Закрытие решений — завершён
Стек, минимальная iOS, JSON-контракты, лимиты, политика дублей, переход после обратной связи, формат хранения, хостинг и прочие вопросы закрыты в `DECISIONS.md` v1.0 (D-001…D-132). До этапа 1 дополнительных решений не требуется; новые вопросы закрываются только новыми записями D.

## Этап 1. Каркас и офлайн — реализован
Репозиторий, Vite + TypeScript strict, ESLint/Prettier, Vitest; структура `src/`; тёмная тема; нижняя навигация; пустые экраны; manifest, иконки и `theme-color`; собственный `sw.js` с precache и версией сборки; workflow GitHub Pages; проверка бюджета JS. Критерии: сборка и локальный предпросмотр пройдены, JS 3.1 КБ gzip (лимит 120 КБ), SW генерируется с версией из содержимого сборки. Осталось: ручные проверки на iPhone (первый запуск, офлайн, обновление SW, скачивание) и инициализация git/публикация — после появления git (D-134).

## Этап 2. Данные и контент — реализован
Модель Deck/Card, домен-валидация, инварианты состояния, адаптер хранения `pq.state.v1` с revision, защитой квоты и экраном повреждённого состояния; экраны наборов, набора, создания набора и карточки, карточки read-only и архива; архивирование/восстановление без каскада, лимиты и сообщения об ошибках. Критерии: данные сохраняются между перезапусками (проверено e2e в headless Chrome: создание набора и карточки, перезагрузка), 50 unit-тестов, JS 10.1 КБ gzip. Ручные проверки на iPhone остаются за пользователем.

## Этап 3. Тестовый движок — реализован
Выбор количества (stepper 1…N, default `min(10, N)`), случайный пул без повторов, перемешивание вариантов Фишером–Йетсом, фиксация первого ответа с guard 300 мс, подсветка верного/неверного и объяснение, переход «Далее»/«Итог», подтверждение выхода без сохранения, сохранение завершённой сессии ровно один раз. Критерии: 66 unit-тестов, e2e в headless Chrome (3 вопроса, блокировка кнопок, сохранение сессии с 3 попытками, повторный тест, подтверждение выхода) — пройдено, JS 12.4 КБ gzip. Ручные проверки на iPhone остаются за пользователем.

## Этап 4. Статистика — реализован
Общая статистика (тесты, верные, неверные, процент), детализация по активным наборам с переходом в набор, история последних 20 попыток и итоги на экране карточки, сброс статистики с подтверждением без удаления контента. Агрегаты считаются из завершённых сессий, архивные наборы скрыты в детализации, но входят в общую статистику. Критерии: 73 unit-теста, e2e в headless Chrome (показатели 3 теста / 4 верных / 67%, скрытие архивного набора, история карточки 1 из 2 · 50%, отмена и подтверждение сброса) — пройдено, JS 13.4 КБ gzip. Ручные проверки на iPhone остаются за пользователем.

## Этап 5. Импорт и backup — реализован
Контракты `personal-quiz-deck` v1 и `personal-quiz-backup` v1: полная валидация до записи, до 20 ошибок с номером карточки, атомарный импорт без частичной записи, добавление нового набора, предупреждение при совпадении названия, экспорт одного файла с предупреждением об открытом тексте, восстановление с подтверждением количеств и полной заменой данных, отклонение несовместимых версий и повреждённых файлов. Критерии: 93 unit-теста, e2e в headless Chrome (импорт валидного файла, список ошибок по карточке, отмена/подтверждение дубля, экспорт, восстановление с заменой, отказ при повреждённом backup без изменения данных) — пройдено, JS 15.7 КБ gzip. Ручная проверка скачивания/выбора файла на iPhone остаётся за пользователем.

## Этап 6. Стабилизация — автоматическая часть завершена
Добавлен интеграционный тест полного пути (импорт → карточка → тест → статистика → экспорт → восстановление → перезагрузка из хранилища) и e2e-стабилизация: активация SW и контроль страницы, офлайн-перезагрузка, обновление SW с плашкой «Обновить» и заменой кеша, базовая доступность (метки кнопок, `aria-current`, скрытые декоративные иконки), отсутствие JS-ошибок. Итог: 97 тестов, JS 15.7 КБ gzip (лимит 120 КБ), бюджеты и блокирующие сценарии закрыты автоматическими проверками. Ручной чек-лист на iPhone (выбор и скачивание файла, ввод с клавиатурой, установка на экран «Домой», офлайн после установки) остаётся за пользователем до приёмки MVP.

## Этап 7. v2: ползунок и набор-пример — реализован
Ползунок 1…N вместо stepper с сохранением дефолта `min(10, N)` (D-135), крупное значение над шкалой, доступность (D-088). Большой набор-пример `docs/templates/qa-core-239.json` (239 карточек; 5 ответов сокращены до лимита 200) с проверкой в тесте шаблонов; автодобавления и кнопки нет (D-136, D-137). Попутно исправлены текст пустого состояния и обрезка названия набора двумя строками. Итог: 106 тестов, JS 15.7 КБ gzip, SW precache 9 файлов. Ручной чек-лист iPhone — за пользователем.

## Definition of Done этапа
Код + тесты + ручная проверка на iPhone + обновлённые документы + запись решения в `DECISIONS.md` (D-005). Этап считается завершённым только после подтверждения пользователя.

Работать небольшими задачами. Не менять стек, зависимости и архитектуру без новой записи D. Для каждой функции добавлять тесты. После этапа обновлять документацию и показывать результаты проверок. Не переходить к следующему этапу без подтверждения пользователя. Все решения фиксировать только в `DECISIONS.md` (append-only).
