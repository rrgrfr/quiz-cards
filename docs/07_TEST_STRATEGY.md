# Стратегия тестирования и критерии приёмки

Версия 1.2 (2026-11-13). Основано на `DECISIONS.md` (D-120…D-126).

## Уровни и инструменты
- **Unit** (Vitest): правила домена — валидация, перемешивание, подсчёт, сериализация.
- **Integration** (Vitest + фейковый адаптер хранения): сценарии, импорт/экспорт, восстановление, ошибки записи.
- **Ручные проверки на iPhone Safari**: всё, что зависит от устройства (офлайн, файлы, обновление SW, очистка данных). Чек-лист — ниже.
- **E2E** (Playwright) отложен до версии после MVP (D-012).

Тесты лежат рядом с кодом; интеграционные используют in-memory реализацию `StorageAdapter`; фикстуры — в `tests/fixtures`.

## Обязательные сценарии

### TC-DECK — наборы
- Создание набора с названием 1–120; пустое имя и имя из пробелов отклоняются.
- Название 121 символ отклоняется; описание 200 принимается, 201 отклоняется.
- Набор с описанием и без; сортировка новых сверху.
- Пустое состояние списка и переход к созданию.
- Редактирование набора отсутствует (нет действия в UI).

### TC-CARD — карточки
- Создание карточки с 4 вариантами и 1 правильным.
- Отклонение 3 и 5 вариантов, пустых после trim, дублей без учёта регистра.
- Отклонение нуля или нескольких правильных.
- Лимиты: вопрос 500/501, вариант 200/201, объяснение 1000/1001.
- Карточка открывается read-only и показывает историю попыток.

### TC-ARCH — архив
- Архивирование карточки исключает её из теста; восстановление возвращает.
- Архивирование набора не меняет флаги карточек; тест активного набора не видит архивный набор.
- Архивный экран показывает сущности и восстанавливает по одной.
- История архивных сущностей сохраняется и возвращается после восстановления.

### TC-IMP — импорт
- Валидный файл: набор добавлен, существующие данные не изменились.
- Неверный синтаксис, `format`, `schemaVersion`, отсутствие `deck`, пустой `cards`, 0 и 1001 карточка.
- Ошибки в одной карточке из многих: не импортировано ничего.
- Некорректный `correctAnswerIndex` (строка, 4, −1, 1.5).
- Дубли вариантов; тексты из пробелов; превышение длин; файл >2 МБ.
- Неизвестные поля игнорируются; импорт проходит.
- Совпадение названия: предупреждение и подтверждение, создаётся отдельный набор.
- Список ошибок содержит номер карточки и поле, не более 20.
- Пример `qa-core-239.json` (239 карточек) валиден и импортируется вручную (D-136).

### TC-BACK — экспорт и восстановление
- Экспорт полной базы: активные и архивные сущности, сессии с попытками, `settings`.
- Восстановление на чистом состоянии.
- Восстановление поверх текущих данных: подтверждение с количеством сущностей, замена.
- Повреждённый файл: отказ, данные не изменились.
- Несовместимая версия: отказ.
- Дубли ID, битые ссылки, несоответствие `questionCount` длине попыток: отказ.
- Импорт файла backup в поток импорта набора: отказ с понятной ошибкой.

### TC-TEST — тест
- Случайный порядок карточек и вариантов; перемешивание не меняет правильность.
- Двойное нажатие не создаёт две попытки (guard 300 мс).
- Ошибочная карточка не повторяется (пул без повторов).
- Число вопросов ограничивается пулом; при 0 карточек запуск заблокирован.
- Значение по умолчанию `min(10, N)`; диапазон ползунка 1…N (D-135).
- Итоговые счётчики и процент (включая округление и «—» при нуле).
- Выход из теста: подтверждение, результат не сохраняется.
- Завершённая сессия сохраняется один раз; прерывание не создаёт попыток.
- Незавершённая сессия не восстанавливается после перезапуска.

### TC-STAT — статистика
- Общие счётчики и процент соответствуют контрольным данным.
- Детализация по активным наборам; архивные скрыты.
- История по карточке — последние 20 попыток.
- Сброс удаляет сессии и попытки, контент и `settings` не меняет; требует подтверждения.

### TC-ERR — ошибки и сохранность
- Ошибка `setItem`: показывается сообщение, успех не объявляется.
- Превышение объёма >4.5 МБ: отказ с советом экспортировать/сбросить.
- Повреждённое состояние: экран ошибки, «Скачать как есть» и «Сбросить», автоматической перезаписи нет.
- Изменение состояния в другой вкладке: при возврате фокуса данные перезагружаются с уведомлением.

### TC-OFF — офлайн и Service Worker
- Первый запуск с сетью, активация SW, повторный запуск без сети.
- Создание, тест, импорт, экспорт офлайн.
- Обновление SW: плашка «Обновить», переход на новую версию без смешивания ассетов.
- Индикатор офлайн при отключении сети.

### TC-NFR — нефункциональные
- JS ≤120 КБ gzip (проверка в сборке).
- Импорт 1000 карточек ≤500 мс; отклик на ответ ≤50 мс (замер на iPhone).
- Контраст ≥4.5, кнопки ≥44 pt, Dynamic Type, VoiceOver-подписи.
- CSP активен, сторонних запросов нет.
- Нет runtime-зависимостей.

## Ручной чек-лист iPhone
1. Первый запуск в Safari, активация SW, повторный запуск в авиарежиме.
2. Установка на экран «Домой», повторный запуск, проверка подсказки.
3. Импорт файла через выбор файла; экспорт через скачивание и share.
4. Восстановление из файла, отмена подтверждения.
5. Полный тест: ответы, «Далее», итог, «Ещё раз».
6. Выход из теста на середине, подтверждение, отсутствие сессии.
7. Архивирование и восстановление набора и карточки.
8. Сброс статистики и проверка сохранности контента.
9. Обновление SW после пересборки.
10. Очистка данных Safari: экран ошибки/пустое состояние, данные не теряются молча.
11. Настройка теста: ползунок 1…N, значение по умолчанию `min(10, N)`, тест на 239 вопросов.
12. Импорт примера `qa-core-239.json`: 239 карточек, тест запускается, название обрезается двумя строками.

## Блокирующие дефекты
- Неверное определение правильного ответа.
- Частичный импорт при ошибке.
- Повреждённый backup уничтожает текущие данные.
- Сброс статистики удаляет контент.
- Архивные карточки участвуют в тесте.
- Завершённые сессии теряются при обычном перезапуске.
- Основной сценарий требует интернет после первого открытия.
- Повторное нажатие фиксирует несколько ответов.
- Ошибка записи скрывается и показывается успех.

## Критерии приёмки MVP
1. Все Must-FR (FR-001…FR-045) реализованы и проверены.
2. Блокирующие дефекты отсутствуют.
3. Unit/integration зелёные, ручной чек-лист пройден.
4. Бюджеты производительности выполнены.
5. Документы обновлены, решения зафиксированы в `DECISIONS.md`.
